# Project Governance

## Maintainers

- The project is maintained by a group of core maintainers from participating organizations.
- Maintainers are responsible for reviewing and merging pull requests, managing releases, and guiding project direction.

## Decision Making

- Major decisions (e.g., new features, breaking changes) are discussed in GitHub Issues or Discussions.
- Consensus is preferred; if consensus cannot be reached, maintainers may call a vote.
- All decisions and votes are documented in the relevant issue or pull request.

## Adding Maintainers

- New maintainers may be nominated by any existing maintainer.
- Nominees should have a history of quality contributions and positive engagement.
- Maintainers are added by consensus of the current maintainers.

## Releases

- Releases are managed by maintainers.
- Release notes are published with each release, summarizing changes and contributors.

## Community Engagement

- The project welcomes contributions from anyone.
- Community members are encouraged to participate in discussions, report issues, and submit pull requests.

## Code of Conduct

- All participants are expected to follow the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Changes to Governance

- Changes to this document require consensus among maintainers and should be proposed via pull request.
